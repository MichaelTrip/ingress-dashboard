## Critical

1. **Cluster failure becomes plausible inventory.** `app.py:246`, `app.py:293`, `app.py:301`, `app.py:386`, `app.py:392`, `app.py:599`. Missing configuration and API exceptions return `generate_mock_*` resources, which are emitted using ordinary update events. The frontend's green Connected badge only confirms its socket connection. An operator can see example hosts and Active statuses while cluster reads fail. → Restrict samples to an explicit, visibly labeled demo mode. Emit per-resource load errors in normal operation, retain any last known good snapshot with a timestamp, and distinguish socket connectivity from successful cluster reads. Source-confirmed; backend failure not executed.

2. **Keyboard users cannot open resource details/YAML.** `templates/index.html:1192`, `templates/index.html:1212`. A generated `div` has only a click listener. Browser inspection confirmed it is outside the tab order. → Add a real, named “View details” button or link inside each card, with visible focus and an accessible dialog title. Keep hostname links separate. Do not wrap the card's existing links in another interactive element.

3. **Export includes resources search hides.** `templates/index.html:876`, `templates/index.html:904`. Search hides the parent `.col`; export checks inline visibility on `.card`. Reproduced with two fixtures: one visible result, two CSV rows. → Derive displayed and exported resources from the same filtering/search result. The button's “currently visible tiles” promise must match the file.

4. **Active is not established by the status data being tested.** `app.py:320`, `app.py:365`, `app.py:407`. An HTTPRoute with parent status entries is Active regardless of its condition values. Gateway listener entries and any GatewayClass status object similarly produce Active. A reported failure can therefore receive a success badge. → Interpret the relevant condition values and their freshness; present unresolved, rejected and unknown states distinctly. Label address presence separately if that is the only fact available. Source-confirmed, without live controller verification.

## Noticeable

1. **The resource list starts far below the task controls should lead.** `templates/index.html:143`, `templates/index.html:614`. At 375px, the seven summary tiles occupy about 963px and the resource container begins around y=1861. At 1280px it begins around y=784. A first-time user must scroll through metrics before even seeing the filters on a phone. → Use a compact contextual summary, with search, filters and resources near the top. Preserve the existing information and familiar controls when agreeing a layout direction.

2. **The Gateway Class filter compares different concepts.** `app.py:316`, `templates/index.html:1109`, `templates/index.html:1173`. HTTPRoutes store parent section/name in `ingress_class`; Gateways store gateway class there. A class selection therefore removes routes whose parent name differs from that class, without establishing whether they belong to a matching Gateway. → Resolve the relationship or split clearly named filter meanings. Do not present a partial result as “no matching HTTPRoutes.” Source-confirmed; not reproduced with Gateway fixtures.

3. **Failed YAML requests give no visible explanation.** `templates/index.html:1473`. The catch handler closes loading UI and writes only to the console. The user is returned to the unchanged dashboard. → Keep the resource identity visible and show a specific inline error with Retry. Initial connection failures also leave the initial loading card in place while only the floating badge changes (`templates/index.html:940`). Add a recoverable error state in the resource area. Source-confirmed, not exercised in the browser harness.

4. **Accessible names and status readability need attention.** `templates/index.html:590`, `templates/index.html:662`, `templates/index.html:1196`, `templates/index.html:1422`. Filter labels are not associated with inputs; theme and modal-close buttons lack names. The Pending badge renders white text on yellow in both captured themes. → Associate `for`/`id`, name icon-only controls, expose selected view state and label dialogs. Give Pending dark text and verify contrast using computed colors, including the animated opacity. Numeric contrast was not audited.

5. **Refresh rebuilds and reanimates the reading surface.** `templates/index.html:975`, `templates/index.html:1139`, `templates/index.html:1189`. Four update handlers each call the full rendering path; every card starts at opacity zero with a delay proportional to its index. The 101st card receives a five-second delay even before considering rendering cost. Logo rotation, status pulsing and banner animation have no reduced-motion fallback. → Preserve stable DOM nodes, update changed values and remove repeated entrance delays. Add `prefers-reduced-motion` treatment. CPU cost remains a profiling lead.

6. **The decoration competes with infrastructure data.** `templates/index.html:55`, `templates/index.html:67`, `templates/index.html:150`, `templates/index.html:169`, `templates/index.html:219`, `templates/index.html:252`. Glass panels, gradient numbers, hover lifts, large pill badges and uppercase labels repeat across the page. Summary tiles lift on hover despite having no action. → Keep the Kubernetes identity and use blue for selection/focus; make status colors carry meaning, use solid readable numbers, and reduce decorative surfaces and motion.
